01

Problem & constraints

From a drone, people and vehicles are a few pixels tall, crowded, and the camera itself moves. A tracker has to keep identities through detector flicker and ego-motion.

02

My contribution

Tracker implementation, batch pipeline and output analysis

  • Implemented SORT from scratch: 7-state constant-velocity Kalman filter, IoU cost, Hungarian assignment, hit/age track management.
  • Ran RT-DETR-L + BoT-SORT over every sequence and wrote MOT-format output.
  • Built a motmetrics MOTA / IDF1 / ID-switch harness.
  • Analysed track statistics and found 32 identities leaking between sequences; fixed the per-sequence reset.

Failures, limits & next steps

✕Fragmented identities

Each detector gap longer than the track buffer starts a new ID; tiny-object flicker is the main source of churn.

✕A bug only the statistics revealed

One model instance with persist=True was reused for all sequences without a reset, so 32 track IDs leaked into the next sequence's first frames. The batch script now resets tracker state per sequence.

Next steps · what would prove it

  • MOTA / IDF1 / HOTA on class-filtered ground truth, for both trackers on identical detections.
  • Fine-tune the detector on VisDrone-DET for small objects.
  • Tune track_buffer and new_track_thresh against IDF1.
