01

Problem & constraints

A tool detector in an endoscopy suite has to run in real time and pass its state to other equipment. Its in-domain accuracy means little if it collapses on a different procedure.

How accurate and how fast is a small detector on endoscopic video, and does that accuracy transfer to a new surgical domain?

02

My contribution

Training, validation, deployment and system integration

  • Converted Kvasir-Instrument to YOLO format and ran 5-fold cross-validation.
  • Compared YOLO11n against a YOLOv8n baseline.
  • Ran an unchanged cross-dataset test on 2,811 laparoscopic frames.
  • Exported to ONNX/TensorRT and profiled latency over 3,451 runs.
  • Built the PySide6 panel and a C++17 termios relay to a simulated microcontroller; wrote requirements and a test plan.

Failures, limits & next steps

✕Missed guidewire

A thin guidewire in an over-exposed view gets no detection at all.

✕Extra box on the lumen

The tool is found at 0.92, but a second box at 0.11 lands on the dark lumen.

Limitations

  • Performance is in-domain only (cross-dataset mAP50 0.17).
  • FP32 engine; the GUI still serves the PyTorch model.
  • Camera-to-UART latency and the event log requirement are open in the test plan.

Next steps · what would prove it

  • Train on Kvasir + m2cai16, test on a third procedure.
  • FP16/INT8 engine served from the GUI.
  • Measure camera → UART byte latency.
